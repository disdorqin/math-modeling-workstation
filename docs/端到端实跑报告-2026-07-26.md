## 4. 暴露的缺陷与修复

### D1 · 图形无法晋升为论文证据（阻断级）

EDA、baseline、模型比较、敏感性四个引擎产出的图形一律注册为 `DRAFT` → `paper_eligible=False`；而 `validate-outline` 要求引用的图形必须 `paper_eligible`。全仓库只有 `task_paper_bridge` 会写 `status="FINAL"`，且**没有任何晋升接口**。结果：README 记载的手工链路永远无法在论文中引用任何一张数据图。

**修复**：新增 `FigureRegistry.get()` / `FigureRegistry.promote()` 与 CLI `promote-figure`。晋升必须挂靠一个已存在的 `paper_ready_approval` 产物，并强制填写审批人与理由，符合"无证据不进论文"的原则。

```powershell
mathworkstation promote-figure --case-id <CASE_ID> --figure-id <FIGURE_ID> `
  --approval-artifact-id <PAPER_READY_APPROVAL_ID> --approved-by human --note "理由"
```

### D2 · paper-ready 审批不可重入（阻断级）

`PaperReadyGate.approve()` 会把实验状态写成 `PAPER_READY`，而 `assess()` 只接受 `SUCCEEDED`。因此第二次审批必然报 `experiment_not_succeeded`——数据画像、EDA 摘要等证据一旦在首次审批时遗漏，就再也无法补充晋升。

**修复**：`assess()` 同时接受 `SUCCEEDED` 与 `PAPER_READY`。

### D3 · `additional_artifact_ids` 未接到 CLI（功能缺失）

`assess()` / `approve()` 早已支持追加证据产物，但 CLI 没有对应参数，能力从命令行不可达。

**修复**：`assess-paper-ready` 与 `approve-paper-ready` 新增可重复的 `--additional-artifact-id`。

### D4 · 数学公式被误判为"未归属数字"（噪声级）

`PaperConsistencyChecker` 的数字扫描不区分正文与数学环境，`$L_2$`、`$\lVert\beta\rVert_1$`、`$\frac{1}{2n}$` 中的下标与指数全部被计为未归属数字。任何写了正经公式的 `model_construction` 章节都必然触发 `UNATTRIBUTED_NUMBERS`，把 `gate` 从 `PASS` 拉到 `REVIEW`。

**修复**：新增 `MATH_SPAN`，在数字扫描前剥离 `$...$`、`$$...$$` 与 `\begin{...}...\end{...}`。正文中的真实数值（`54.825`、`4.07%`）仍被正常检出。

### D5 · 手工链路产不出 `paper/final.md`（阻断级）

`complete-paper-draft` 写的是 `paper/paper_final.md`，而 `prepare-submission` 与 `export-case` 读的是 `paper/final.md`——只有 LLM 循环精修会写后者。于是不使用 API 的链路在投稿环节直接死路，与 `docs/reproducibility.md`「确定性路径不需要 API key」的承诺矛盾。

**修复**：`complete_paper_draft()` 同时写入并注册 `paper/final.md`。精修循环仍会用其接受版本覆盖两个文件，LLM 路径行为不变。

### D6 · DAG 硬性要求 LLM 精修才能导出（阻断级）

`refinement_loop` 为关键节点且不可降级，`final_review` 与 `export` 均在其下游。现有 `skip()` 会阻断全部下游，无法用于"有意不跑该分支"。

**修复**：`refinement_loop` 标记 `may_degrade=True`；新增 `WorkflowController.degrade()`、`WorkflowService.degrade_node()` 与 CLI `degrade-node`。DEGRADED 属于 success-like，下游解除阻塞，同时把审批人与理由永久写入 `decisions.jsonl`——是"记录在案的省略"，不是"静默跳过"。

### D7 · 图形从不进入论文正文（阻断级，对目标能力）

`_render_final_manuscript()` 把 `[figure-xxxx]` 替换为「（图 N）」后即丢弃，既不插入图片，LaTeX 也不生成 `\includegraphics`。图形全流程（生成→注册→晋升→引用→一致性校验）都能跑通，唯独最终稿里一张图都没有。投稿预检里那段检查 `\includegraphics` 是否存在的代码因此从未被触发过。

**修复**：
- `complete_paper_draft()` 从各章节 `context.json` 收集 `allowed_figures`，构建 `figure_id → (path, title)` 映射；
- `_render_final_manuscript()` 在首次引用所在段落之后插入编号图片与图题；
- `markdown_to_latex()` 将 Markdown 图片转为 `figure` 环境 + `\includegraphics` + `\caption`。

### D8 · 图形编号映射键不匹配（D7 的隐藏子缺陷）

`replace_figure()` 用正则捕获组 `match.group(1)`（裸十六进制）作为编号字典的键，而图形注册表用完整的 `figure-xxxxxxxxxxxx`。两者无法 join，D7 的修复初版静默失效——编号正常但图片始终插不进去。

**修复**：编号字典改用完整 `figure_id` 作键。

### D9 · 投稿预检的图形路径解析仅在 Windows 可用（跨平台阻断级）

```python
image_path = root / image.replace("/", "\\")   # 修复前
```

产物路径以 POSIX 形式存储；在 Linux / macOS 上把 `/` 换成 `\` 会使整条相对路径塌缩成一个文件名，于是**每一张实际存在的图都被报成 `FIGURE_MISSING`**。这条在 D7 修复前无法被发现，因为此前根本没有 `\includegraphics` 可供检查。

**修复**：改用 `root.joinpath(*PurePosixPath(image).parts)`。

### 附：非阻断的观察项

- `register-dataset` 返回 `{artifact, dataset}` 嵌套结构，而 `register-artifact-dataset` 直接返回 dataset，脚本取 `dataset_id` 的写法不一致。已在 `DataService.register_uploaded()` 返回值中补充顶层 `dataset_id` / `artifact_id`（向后兼容）。
- `submission.sanitize_submission_markdown()` 内含一串硬编码的中文图名黑名单（`数值变量分布`、`候选模型…` 等）。当前可用，但每加一类图就要改正则，建议改为按注册表清理。
- `mark-stale` 是修改已完成节点的唯一手段；`retry-node` 不接受 `SUCCEEDED`。重新绑定提纲这类正常操作只能靠 `mark-stale`，语义上偏重。

## 7. 后续建议

1. **补 LLM 路径实跑**：在可直连中继端点的机器上执行一次完整 `run-auto-pipeline` + `run-refinement`，本次全部未验证。
2. **把手工链路纳入 CI**：`run-task-paper` 覆盖的是旁路，本次九个缺陷全部位于 DAG 主链路且都是 CI 未触及区域。建议增加一个"无 API 全链路"冒烟作业。
3. **图形入文纳入结构门**：`CompletePaperContract` 目前不检查最终稿是否含图。建议对声明了 `figure_ids` 的提纲，强制最终稿存在对应图片引用。
4. **跨平台 CI**：D9 是纯 Windows 假设导致的缺陷，建议 CI 矩阵至少包含 ubuntu-latest。
