```
┌─────────────────────────────────────────────────────────┐
│  B层(可选增强): 本地RAG                                │
│   corpus → 分块 → 向量化 → SQLite检索                  │

├─────────────────────────────────────────────────────────┤
│  C层(本次新增): 精华模型卡片 config/knowledge/          │

```

## 二、各层职责

### A层(已有, 不新增)
- `config/hmml.json`: 5大类→子域→97节点, 方法树
- `config/model-catalog.json`: 32方法 + 14 task_types, LLM 选模型白名单
- 作用: 模型"能不能用"的权威约束

### C层(本次新增核心) — config/knowledge/
- **来源**: 姜启源《数学模型》29章(本机高教社论文/数学建模资料) + 高教社376篇C题优秀论文
- **形式**: 每模型一个中文 md 卡片 + 索引 `config/knowledge/index.json`
- **卡片字段**(仿 Beacon corpus + 工作站风格):
  ```markdown
  # 模型名 (model_id)
  ## 适用场景
     判别特征 / 关键词(何时用)
  ## 核心公式
     LaTeX 公式
  ## 建模步骤
     1..n 步骤
  ## C题适用性
     适合哪类 C 题 / 数据条件
  ## 论文佐证
     哪年哪篇优秀论文用了, 如何用(证据)
  ## 易错点
     常见坑 / 违背假设
  ```
- **首批范围**(对齐 catalog 32方法, 优先 C 题高频): 线性规划/整数规划/非线性优化/回归族/时序族/分类族/评价族(AHP/熵权/TOPSIS/灰色关联)/聚类族/灰色GM11/排队论/蒙特卡洛/微分方程/图与网络/动态规划/插值/马氏链/PCA
- **索引**: index.json 记录 {model_id, 卡片路径, 关联task_type, C题适配度}

### B层(可选, 后置)
- 参考 Beacon: corpus → SQLite + embedding → analyst/modeler/writer 注入
- **本次不做实现**, 保留开关设计

## 三、注入点(工作站管线)
- C层卡片在 `model_plan` 阶段检索(仿 HMML 注入), 给 LLM 提供"该模型怎么用、论文怎么证明它"的上下文
- 检索: 确定性关键词匹配(契合"可追溯"), 可选 RAG
- 全层非阻塞(检索失败不中断流水线)
