## 3. 国赛优秀论文实测结构（2018 / 2020 / 2023，PDF 章节标题抽取）

实测抽取到的真实章节骨架（以 A092、B226、2018 高温服装、2018 RGV 调度等为代表）：

```
摘要（单列、自足、含关键词）[部分附英文摘要 Abstract]
一、  问题重述         （问题背景 + 逐子问题重述）
二、  问题分析         （对每个子问题做定性分析，交代建模思路）      ★ 我们无此独立章节
三、  模型假设
四、  符号说明
五、  模型的建立与求解  （按 子问题一/二/三 组织：建立—求解—验证 一体）
…     灵敏度分析 / 稳健性分析
…     模型的评价        （优缺点）
…     模型的改进 / 推广                                ★ 我们无此独立章节
…     参考文献
附录  （代码、数据、附图）                              ★ 可选
```

不同年份写法略有差异（2018 多用阿拉伯数字 1./2.，2023 多用"一、二、三"；问题分析/假设/符号顺序偶有微调），但**核心栏目高度一致**。

## 4. 对照表：国赛结构 vs 我们 12 节

| 国赛栏目 | 我们 12 节对应 | 匹配度 | 备注 |
|----------|----------------|--------|------|
| 摘要（自足、含关键词） | abstract | ✅ 基本匹配 | 见 §5 风格强化点 |
| 问题重述 | problem_restated | ✅ 匹配 | 国赛标题叫"问题重述"，我们叫"引言与问题重述"，含义一致 |
| **问题分析** | **（无）** | ❌ **缺失** | 国赛每篇都有，承上启下 |
| 模型假设 | assumptions | ✅ 匹配 | |
| 符号说明 | notation | ✅ 匹配 | |
| 模型的建立与求解（一体化） | model_construction + model_solution | ⚠️ 拆细 | 我们的拆分更工程化（证据链），保留 |
| 结果分析 | results | ✅ 匹配 | 国赛常并入"建模与求解"内 |
| 灵敏度/稳健性 | sensitivity | ✅ 匹配 | |
| 模型的评价（优缺点） | strengths_weaknesses | ✅ 匹配 | |
| **模型的改进/推广** | **（无）** | ❌ **缺失** | 国赛优秀论文普遍有 |
| 参考文献 | references | ✅ 匹配 | |
| 附录 | （无） | ◯ 可选 | 主要在 code/产物，论文未强制 |

**关键差异结论**：
1. **缺失「问题分析」**：国赛优秀论文的顺承逻辑是「重述 → 分析 → 建模」，**先交代每个子问题怎么入手、选什么方法、为什么**，再进入建模。我们直接从 data_analysis 跳 model_construction，缺少这一"说理"环节。
2. **缺失「模型的改进/推广」**：国赛通用收尾是「结论 + 优缺点 + 推广/改进」，展示思考的深度与泛化。我们止于 conclusion/strengths_weaknesses，未显式留"推广"口子。
3. **摘要自足度**：国赛摘要强调**单页自足、图文并茂、给出具体数字结果**（"提高了 xx%"/"误差 0.xx"），弱化"本文建立了模型"式空话。我们的摘要合同已要求 目的/方法/结果/稳健性，风格接近，但可强化"结果量化与配图"。
4. **建模章节组织**：国赛按"子问题"横向组织（问题一/二/三各成小节），我们按"建立/求解/结果"纵向切。二者皆有效，但因我们走证据链（claim→artifact→figure），纵向切片是工程必需，**不宜强行改为横向**。

## 5. CUMCM profile 画像 —— 哪些能融入 / 哪些暂缓

按任务要求"不干扰主线、不乱改代码"，融入分三档：

### 5.1 ✅ 建议融入（可作为**可选章节/可选增强**，不破坏现有 12 节）
1. **新增可选「问题分析」(problem_analysis)**：放在 data_analysis 之后、model_construction 之前。给每个子问题一段"建模思路分析"，承接证据链（可引用已批 claim）。与现有时序/动量注入相同的"条件式追加"模式，默认不启用，开关启用。
2. **新增可选「模型的改进/推广」(model_generalization)**：放在 strengths_weaknesses 之后、conclusion 之前。仅作为可选小节，由开关控制，不改变结论主链。
3. **摘要/关键词产出增强**：摘要末尾自动附**关键词**（从 claims + 方法名提取 3-6 个），符合国赛"摘要+关键词"惯例；结果段落鼓励量化（把 figure 证据与数字结果一并给出）。

### 5.2 ◯ 可暂缓观察（不急着落代码）
- 「模型的建立与求解」按子问题横向重排：与证据链纵向切片架构冲突，**暂缓**；先保持现状，后续若需要可在 model_solution 内加"子问题小结"。
- 「附录」单列：代码/数据已在 artifact registry 留痕，不必在论文正文强行加附录章节，**暂缓**。

### 5.3 ⛔ 不建议强行融入
- 把 12 节压缩成国赛的"一~五+附录"短结构：会丢掉我们的证据门/敏感性/建模拆分，降低可复现性。**不建议**。
- 去掉 data_analysis：国赛数据类题（C 题）同样重视数据处理，data_analysis 是我们的加分项，**保留**。

## 6. 融入建议（具体、可落地、不破坏主线）

> 遵循"可选开关 + 条件式注入"模式（与现有 C-type 的 timeseries/momentum 注入同构），**默认关闭、不影响既有输出与既有测试**。

1. `default_outline` 增加两个可选章节位：
   - `problem_analysis`（问题分析）：`data_analysis` 之后、`model_construction` 之前；
   - `model_generalization`（模型的改进与推广）：`strengths_weaknesses` 之后、`conclusion` 之前。
   通过 `PaperOutline` 的可选集/`default_outline` 参数旁路控制（类似 is_c_type），**不加入 REQUIRED_SECTIONS**（保持 12 节为最小强制集）。
2. 摘要层：在摘要生成阶段追加「关键词」行，并鼓励量化结果（可选，不动合同 required_any）。
3. 配套 `SECTION_CONTRACTS` 可选条目 + 测试：新增两章时有基本内容守门（可选章节软校验），不纳入强 `REQUIRED_SECTIONS`，避免破坏权威集锁测试。
4. 文档化：把本报告 §5 画像写入本报告/设计，作为后续任务落地依据。

**落地说明**：以上均属"可选增强"，**本轮仅给建议与设计，未改 src/ 代码**，符合任务"不乱改代码、只出报告"的边界；如导师批准，可在后续任务把 §6 落地并有测试覆盖。
