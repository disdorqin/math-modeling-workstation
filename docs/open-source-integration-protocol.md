# 开源项目融合协议(Open-Source Integration Protocol)

**状态:** v1.0 (2026-08-05) · 起草: claude_code
**目的:** 让三个徒弟(opencode/freebuff/cline)按严格流程,把网上的开源数学建模项目**检索→确认→复刻/融合**进我们的工作站,我(导师)验收时**一比一对应开源项目**。

---

## 一、核心流程(每项融合必走)

```
1. 检索: 上网搜开源项目(GitHub等),确定目标项目
2. 确认: 读它的 README/代码,确认其能力、许可、可复刻性
3. 复刻/融合: 把它的有效方法/模块融合进我们的 src/ 或流程
4. 测试: 跑测试,确保不破坏既有
5. 上报: 说明融合了什么、来源、对应关系
6. 验收: 导师一比一对照开源项目,确认融合准确
```

## 二、一比一验收标准(导师验收用)

| 项 | 要求 |
|---|---|
| **对应关系** | 我们融合的每个功能,能在开源项目里找到对应实现 |
| **许可** | 融合前确认开源项目 License,可复刻/融合 |
| **不改语义** | 融合的方法逻辑与开源项目一致(不是"借个名字") |
| **有测试** | 每个融合功能有测试,验证与开源项目行为一致 |

## 三、待融合的开源项目方向(参考)

基于 cline 计划 + 用户指令,候选方向:
- **数学建模 agent**:MM-Agent(HMML方法库)、MathModelAgent(多agent协作)
- **研究/写作**:AI-Scientist(实验闭环)、STORM(多视角)、PaperQA(引用)
- **框架**:LangGraph(编排)、PydanticAI(结构化agent)

## 四、分工建议

| 徒弟 | 方向 | 验收 |
|---|---|---|
| opencode | 检索+融合建模方法(如MM-Agent) | 导师一比一验收 |
| freebuff | 检索+融合框架(如LangGraph/PydanticAI) | 导师一比一验收 |
| cline | 检索+融合写作(如STORM/PaperQA) | 导师一比一验收 |

## 五、铁律

- **先检索确认,再融合**(不凭记忆)
- **一比一对应**(融合的每个功能有开源来源)
- **许可合规**(确认License可复刻)
- **不破坏既有测试**

*三个徒弟遵守。导师严格验收,一比一对照开源项目。*
